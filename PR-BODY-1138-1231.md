- `src/schema.rs` and `src/path.rs`: both said "migrations 1 and 2 named no
  `COLLATE`" for the two path columns. Migration 1's `path` column
  (`create_project`, `schema.rs`) has since been amended to declare

  `yadgarhq/project`'s ledger 769): the per-module allow is the accepted

  `project.proto` source this repository does not own (D16). Also corrected
  the stale `project/src/lib.rs:58` line reference to `:65`, which drifted
  when `yadgarhq/project`#24 made the equivalent fix there.

No production code changed in either.

## Why

Ledger 1138: `schema.rs:259-261` and `path.rs:96-99` still describe both
migrations as silent on collation, but `create_project`'s SQL at
`schema.rs:160-161` already carries an explicit `COLLATE` clause on `path`.
Left uncorrected, a reader trusts the comment over the code it sits beside.

Ledger 1231: this repository's `src/lib.rs` carries the exact same refuted
proto-indent claim that `yadgarhq/project`'s ledger 769 corrected — both
repositories vendor `project.proto` and hit the same
`clippy::doc_lazy_continuation` lint, and both comments pointed at the same
non-fix. Folded into this PR because it is the same class of stale-comment
fix, found while verifying 769/790 for the sibling repository.
